## Hard requirements (Boss)
- **R-001 one-button reset / “emergency exit”** (2026-11-03, lesson from File Pilot, where only a Windows reinstall helped): every Windows integration (Win+E, folder verbs/default handler, explorer.exe proxy/IFEO, context menu entries, autostart, environment variables/PATH, shortcuts, file associations, hotkeys) must be **fully undoable with one button** – in the app **and** via a standalone recovery tool that also works when the app itself does not start (including Safe Mode). Every change is saved beforehand with its original value in a journal; reset restores exactly the original state. Mandatory test: integration on → reset → registry/environment identical to the snapshot before. Applies from M7, take it into account in the architecture before that.

## Insights / gotchas
- The release exe is GUI subsystem: never `println!` (panics on missing stdout, `panic=abort` kills the app) → `let _ = writeln!(...)`.
- PowerShell `& exe` does not wait for GUI exes → in CI `Start-Process -Wait -RedirectStandardOutput`.
- Sandbox: the Xvfb UI test needs `libxkbcommon-x11-0`; start with `SLINT_BACKEND=winit-software xvfb-run ...`.
- CJK layout (zh/ja): Linux has no CJK glyphs unless `fonts-noto-cjk` is installed, and missing glyphs measure too narrow → the `e2e-linux` job installs that package before the gallery. zh and ja have one plural form (`plural_index` 0). Traditional Chinese is not mapped to `zh`. Access keys for CJK keep the Latin letter visible (`替换(&R)` strips to `替换(R)`, and the label must be exactly that).
- Windows cross-check is possible locally for pure Rust crates: `cargo clippy -p explorer-core -p explorer-fs --target x86_64-pc-windows-msvc` (not the app crate, because of Skia/MSVC).
- CI status via GitHub MCP (`actions_list` / `get_job_logs`), no `gh`.
- Slint: `text: prop` on a TextInput is one-way and **breaks while typing** → always `text <=> prop` (in-out) for editable fields.
- Slint: `viewport-y` is deprecated → `content-y`.
- Background→UI: `slint::invoke_from_event_loop` + generation counter; UI state in `thread_local!` (Rc is not Send).
- `cargo fmt` wraps long lines → check Python string replaces afterwards (`assert s.count(old)==1`).
- E2E under Xvfb without a window manager: `xdotool windowfocus` instead of `windowactivate`; debug trace via `EXPLORER2_TRACE=1` (stderr).
- Never write the trace log into a watched folder, except to test the throttle.
- Trace lines: `at=` = ms since process start (cold-start measurement), `data_ready=` = ms navigate→data ready, measured in the loader thread (data latency, budget check). Slint initialises the renderer only at the first frame **after** the loop starts → “event loop running” is NOT a window-ready marker; `set_rendering_notifier` is not available with software renderers → do not use it as a marker.
- GitHub runners (Windows) have no GPU OpenGL → Skia falls back (works, costs **~450 ms** start time; the software renderer starts in 43 ms).
- Windows runners: sporadic OS stalls in the file system up to 1.5 s (Defender/indexer after mass creation, ~2 of 9 runs) → always evaluate perf with the raw OS measurement next to it (`bench` prints `raw: first_entry` per run).
- Slint: renderer via `slint::BackendSelector::new().backend_name("winit").renderer_name("skia"|"software").select()` **before** the first window; `"skia"` falls back on its own, `"skia-opengl"` does not. `SLINT_BACKEND` always wins.
- `xprop` shows `_NET_WM_ICON` empty in pretty mode → read the raw data with `-notype 32c` (the icon was set).
- Mesa for Windows GL tests: take the **MinGW** package (the 26.x MSVC package has no software OpenGL); an app-local `opengl32.dll` is used by the probe + Skia.
- GPU probe costs vary a lot (runner 3–581 ms, Mesa llvmpipe 239 ms) → that's why it only runs in the background.
- The first-start gate varies a lot with the VM for the **same code** (#54: 1178 ms, #55: 731 ms; #57: 2709 ms at `probe_ms` 521 vs #58: 677 ms at 84.5) → when red, compare the numbers first (`window created` comes before any app code, `probe_ms` is in the log as a VM metric), don't optimise blindly; time gates are collected and only thrown at the end of the matrix, E2E runs even after a red gate.
- The very first start on a fresh Windows VM pays one-off costs (window creation 755 ms instead of ~5 ms: file cache/fonts) → the cold-start budget 300 ms is checked on normal starts (cache) best-of-3, the first start only for plausibility < 1 s and reported.
- **Measure UI states by pixel** (`convert img -format '%[pixel:p{x,y}]' info:`), never by eye on scaled-down screenshots – a supposed render bug (focused row “without” selection colour) was a reading error.
- Slint: `changed prop` does **not** fire at initialisation → a newly instantiated repeater instance (e.g. a new split pane) misses a sequence order set before. So couple focus to state (`changed active` + `init`), not only to counters.
- Slint: functions of repeater instances cannot be called from Rust → orders (scroll, edit, focus) via `*-seq` counters in the model data + `changed`.
- Slint: root `FocusScope` with `key-pressed` as a fallback, so shortcuts work even without a focused list.
- Always measure throttles/rate limits from the **start** of an action, not from its end (otherwise overlap on a slow machine).
- E2E: own log per block (`trace-<n>.log`), otherwise failures cannot be analysed afterwards; `EXPLORER2_TRACE_KEYS=1` logs every key with its pane.
- The security check blocks `rm -rf $VAR` in `bash -c` strings → unique temp folders instead of deleting.
- Long CI logs: `get_job_logs` with `return_content=false` → load the URL via `curl` and grep (the tail is flooded by cache upload lines).

- Slint DnD: the TouchArea must be a **child** of the `DragArea` (as a sibling above it, it swallows the press); `DragAction` is not public in Rust → callbacks return int (0/1/2), Slint maps it. `pure callback` for `data:` bindings.
- Python replaces in files with Windows paths: **raw strings** (`r"..."`) – `\a`/`\b` otherwise become control characters.
- PowerShell 7 has no `Get-Clipboard -Format FileDropList` → `shell: powershell` (5.1) for clipboard tests.
- Windows PowerShell 5.1 `Get-Clipboard -Format FileDropList` returned empty in CI although `FileDrop` was on the clipboard → for tests use `[System.Windows.Forms.Clipboard]::GetFileDropList()` (= the route other apps take).
- CI uses the **latest** stable (new Clippy lints, e.g. 1.99 `chunks_exact_to_as_chunks`) → `rustup update stable` locally before pushing.
- Windows: paths can contain **8.3 short names** (`C:\Users\RUNNER~1\…`, e.g. from `%TEMP%`), shell/Recycle Bin return long names → never compare paths raw: canonicalise the parent folder + case-insensitive (`undo::same_location`).
- Windows Recycle Bin (`trash` crate): `TrashItem.name` is the **display name** (extension hidden with default settings: “weg” instead of “weg.txt”) and is used as the target name on restore → match via stem + extension of the `$R…` file (`item.id`), set `item.name` to the real name before `restore_all`.
- `windows` crate `#[implement]` expands to `windows_core::…` → `windows-core` is needed as a **direct** dependency.
- Never start modal Windows loops (`SHDoDragDrop`, `TrackPopupMenuEx`) directly from a Slint callback that touches Slint state afterwards → start via `slint::Timer::single_shot(ZERO)`; after `DoDragDrop` dispatch the pointer release via `dispatch_event` (OLE swallows the release).
- Slint creates the native window only **some time after** the event loop starts (not necessarily in the first timer) → HWND-dependent setup (drop target) with retry until `window_handle` ≠ 0 (CI #32/#33: “Invalid window handle”).
- Only start an OLE drag while the primary button is **still pressed** (`primary_button_down`) – otherwise OLE waits for the next input and drops at the next mouse move.
- Windows dialog titles (Properties) show names **without** a known extension (“a Properties”) → don't match tests on “a.txt”.
- PowerShell `New-SmbShare`: the comment is called `-Description` (not `-Remark`, that's the NetAPI name); the runner only has admin shares → create an own share for network tests.
- SendKeys: `%` = Alt, `+` = Shift, `^` = Ctrl → send them literally as `{%}`, `{+}`, `{^}`.
- CI does not run on pure doc commits (`paths-ignore`) → finishing docs needs no run of its own.
- **Slint: a repeater over an `int` (`for x in n`) rebuilds all instances on EVERY re-evaluation** (models are compared by pointer, `int` creates a new one each time) → hover/double-click get lost. For dynamic lists always use a stable `VecModel` from Rust, only grow/shrink at the end. Check with `init => { debug(…) }`.
- UI texts only with characters Segoe UI surely has (Latin, umlauts, arrows ←→↑↶↷›); draw symbols like ▾ ✓ as `Path`/Rectangle – **measured**: one “▾” cost +1.2 s at the first frame on a fresh VM (CI #50 vs #51); trace marks `init done`/`run`/`event loop running` narrow the start down.
- Slint: `visible: false` does **not** save building/layout at the first frame → put rarely used overlays (palette, dialogs) under `if …`, focus via `init` (CI #53).
- Slint TouchArea: `clicked` comes **before** `pointer-event(up)` → reset state that `clicked` checks only in the pointer event.
- Slint: `row`/`col` are reserved on every element (GridLayout) → don't name a property `row`.
- Windows Server runners: PNG thumbnails yes, **BMP no** (no provider) → thumbnail tests with PNG; `shell::thumbnail` reports `preview` honestly.
- X11/Xvfb: one mouse-wheel click can arrive twice → throttle wheel actions; never put the E2E trace into the watched folder (refresh loop).
- Windows E2E: `scripts/e2e-windows.ps1` (SendKeys + SetCursorPos/mouse_event, window maximised, runner screen 1024×768, DPI 1.0); work around the foreground lock with an Alt press before `SetForegroundWindow`.
- Always restore from the Recycle Bin against the snapshot **before** the action (the same original path can be in the Recycle Bin several times).
- Slint std-widgets export a global `Palette` → don't name an own component `Palette` (the command palette is called `CommandPalette`). `Palette.color-scheme` is in-out: setting it = std widgets fixed light/dark; Slint colours std widgets itself with the Windows accent (`DwmGetColorizationColor`, hue only).
- Palette commands run via `Timer::single_shot(ZERO)` **after** the palette closes: otherwise the focus return to the list wins against the dialog focus, Enter in the dialog goes nowhere (CI #60 W41, also applied to “Endgültig löschen” (delete permanently)/“Papierkorb leeren” (empty Recycle Bin) from the palette).
- Windows E2E: shell dialogs (Properties) come asynchronously and sometimes late → poll instead of a fixed wait and wait until they are closed (otherwise a late dialog steals the focus of the following steps, CI #60 W11→W17).
- `e2e-windows.ps1` runs under **Windows PowerShell 5.1** with `ErrorActionPreference = 'Stop'`: every stderr line of a native program (e.g. `reg export` on a missing key) aborts the script, even with `2>$null` → in such functions set `$ErrorActionPreference = 'Continue'` locally (CI #62).
- PowerShell 5.1: functions unwrap a one-element array, and `.Count` of a single `CimInstance` is `$null` → always wrap results in `@(…)` before checking `.Count` (CI #66).
- Windows E2E: what **explorer.exe** starts (Win+E, desktop double-click) inherits the environment of the shell, not that of the test script → `EXPLORER2_TRACE_FILE`/`EXPLORER2_CONFIG_DIR` don't apply there; check such starts on the process (`Win32_Process` CommandLine), CI #65.
- Windows command line: `"C:\"` (drive from `%1`) arrives as `C:"` per the CRT rules (`\"` = quote) → always pass start arguments through `launch_arg`.
- Never run tests against the real registry with `reset()` (it sweeps the real integration locations = would remove an active integration of the developer) → `reset_with(.., &[])`.
- Never run snapshot tests over all of `HKCU\Software\Classes` (MuiCache and others change by themselves on program start) → only export the integration areas.
- Sandbox disk quota: `target/debug` grows to >10 GB → on “Bus error” in the linker/“no space”, `rm -rf target/debug`; delete the Windows cross-check (`target/x86_64-pc-windows-msvc`, several GB) right afterwards.
- CI job `e2e-linux` only builds what's in the workflow → build helper bins (`explorer2-recover`) that an E2E block needs there too (`-p explorer-integrate --bins`); locally they happen to be in `target/release` (CI #68).
- Start guard (M8.3a): a start that doesn't run for 5 s counts as a crash → E2E kills shortly after the start would trigger the safe start; the Linux SIGTERM handler clears the guard (intended end), the Windows smoke matrix runs 8–9 s each. New tests with a quick kill: use an own `EXPLORER2_CONFIG_DIR`.
- Single instance (M8.3b): tests that need two windows with the **same** config folder start the second with `--new-instance` (otherwise it hands over to the first and exits); processes started by Windows inherit the test's config folder → hand over to the test window, the `launch arg` trace still comes (it's before the hand-over).
- Memory endurance tests: always evaluate growth **against the caches** (the tile image LRU up to 96 MiB fills up piece by piece) and measure in two phases – a leak keeps growing in phase B, a cache doesn't (CI #72 → #73). The app reports the cache in `thumbs loaded … bytes=`.
- GitHub MCP gone/reconnecting: the public API also works without login (`api.github.com/repos/TeslaV0D/explorer-2.0/actions/runs?branch=…`, `…/actions/jobs/<id>/logs` with `curl -L`).
- Perf gates on CI VMs: Windows VMs vary up to 2.5× (index build 200 vs 543 ms) → don't hug the budget, build with headroom (locally ≤ ~1/3 of the budget); measuring single-threaded (`EXPLORER2_INDEX_THREADS=1`) shows iterator/closure load (10 ns/entry instead of ~1).
- Endurance tests with the keyboard: never run past the end of a list – `Enter` on a file opens it in the default program (Windows: Notepad steals the focus, “keys arrive, nothing happens”, CI #75–#78); log foreign foreground windows + count them as a check.
- Linux/notify: a new folder is **reported before it is watched** → files from that moment are missing without an event → `live::RECHECK_NEW` (reconcile the folder 1 s later). Recursive inotify also sets one watch per folder (sandbox: 5 s for 4,230 folders) → never before making a loaded index searchable; Windows uses one handle for the whole tree.
- Windows CI VM: the cold system disk is IOPS-limited (`C:\Windows` cold 5k entries/s at 10 % CPU, warm 207k/s) → the initial index build of `C:\` takes > 15 min there; gate on `D:\` (local SSD), `C:\` only measuring runs with a time limit (`drive --probe`).
- E2E click targets in the settings panel are fixed coordinates (`T_RESET`, `T_DARK`, `PANEL_HW_*`) → a new section shifts everything below it; after panel changes check screenshot + coordinates (S1.4a: reset 502 → 625).
- Slint: never compute the size of a layout child from `parent.width` (`width: min(240px, parent.width * 0.3)` in a HorizontalLayout = binding loop → panic “Recursion detected” on start) → `preferred-width` + `min-width` + `horizontal-stretch`.
- Detect placeholder paths (`::…`) in `navigate_tab` **before** `std::path::absolute`, otherwise `::suche:x` becomes `<cwd>/::suche:x`.
- Slint: a `Rectangle` doesn't block clicks – overlays/panels need an empty `TouchArea {}` as the first child, otherwise clicks on empty areas land in the list below (CI #89 [71e]).
- E2E shell: `last 'x' >/dev/null` is **always true** (exit code of `tail`) → always check occurrences with `grep -q 'x' $LOG`. Never put fixed click coordinates under text of variable length (fonts/wrapping differ between sandbox and runner); for a red click test look at the end of the trace first (e2e-ops prints it at [71e], CI uploads `trace-*.log`).
- Modal dialogs keep the focus (`changed has-focus` → `focus()` again while open).
- Slint (1.18): use a `let` variable in a callback only **once** – the generated Rust code moves it at the first use (`borrow of moved value`); the second time via the property (`self.text`).
- UI dump: open `PopupWindow`s (menus) have their **own item tree** on the window (`WindowInner::active_popups()`) → walk them separately and offset by `PopupWindowLocation::ChildWindow(p)`.
- The Slint test API `ElementHandle` (i-slint-backend-testing) needs compiled-in debug info (`element_count()`), otherwise it finds nothing → for the UI dump use `ItemRc::visit_descendants` + `accessible_string_property(Label)` from `i-slint-core` directly (pin the version **exactly** like Slint, bump it along with Slint updates). Every `Text` has its content as `accessible-label`.
- Never edit a running bash script: bash reads it line by line as it goes (the offset shifts) → finish the run first, then change it.
- Random names in tests: temp folders are called `.tmpXXXXXX` (random letters) → never query single letters in tests, the root is in the index.
- Slint: components that inherit from `Rectangle` must not have their own property `color` (deprecated, = background) and no function `focus` → `tint`, `take-focus`; `mouse-cursor: text` in a component with a `text` property means the property → `MouseCursor.text`.
- Concatenating SVG paths: a lower-case `m` at the start of a `<path>` is absolute, but relative after concatenation, and the pairs after it are relative lines → always write `m x y …` as `M x y l …` (otherwise broken icons: x, arrow right, usb).
- Slint: never bind breakpoints to `root.width` when they change widths in the layout (window layout → width → breakpoint → layout = binding loop, compiler warning “may panic”) → set values in `changed win-w`/`init`. Slint 1.18 has a built-in `Tooltip` element (child with own content = own look).
- Slint has no `while`/`for` in functions → loops (e.g. finding the next selectable menu entry) as a callback to Rust.
- While an E2E is running, **no `cargo build --release`** (the tests keep restarting the release exe) → check Slint changes with `cargo check -p explorer2` then.
- Slint: animate the appearance of a newly created element = `property <bool> shown; init => { self.shown = true; }` + `opacity: shown ? 1 : 0` with `animate`; fading out an always-present overlay = `visible: open || self.opacity > 0.02` + animated opacity.
- A registry theme written directly (test) sends **no** WM_SETTINGCHANGE → winit notices nothing, our watcher does; winit sets the title bar itself on real system changes → we set it again 400 ms later.

- Slint translations (1.18): language `""` or `"en"` = the source texts (bundle index 0); `select_bundled_translation` works only **after** the first component exists and needs at least one `.po` in the bundle dir (else build error) → `lang/de/` always exists. Plurals in `.slint`: `@tr("{n} item" | "{n} items" % count)`. Placeholders that a translation may reorder must be written `{0}`/`{1}`, not `{}` (the catalog test compares placeholder sets).
- i18n without contexts: **one English text = one translation everywhere** → a new/renamed source text must not equal an existing one with another meaning (L3: “System” for the colour scheme merged with the file attribute “System”; now “System default”). Renaming source texts: carry the translations over and compare the multiset of all `msgstr` before/after. UI scripts in other languages: `EXPLORER2_LANG=<code>` + `ui-lib.sh` translates the German target names via `scripts/ui-lang-map.py`.
- i18n extractor: a strict string reader on *all* strings gave up at `\x89` (byte string) and silently skipped the rest of the file → other strings are only skipped, and `collect` fails if a file has more translation calls than were read (L2). Unit tests always see the English source (no test sets a language except the i18n crate's own); a test that needs German must not exist outside `explorer-i18n` (the language is process-global, tests run in parallel).
- **`ubuntu-latest` = Ubuntu 26.04 since 2026-11-10**: there `xdotool key F2` arrives as **Alt+F2** (the app rightly ignores it; CI #139/#140, found with `EXPLORER2_TRACE_KEYS`, which now also logs the raw key `key raw … text=[f705] alt=true`) → job `e2e-linux` pinned to `ubuntu-24.04`. On a sudden red E2E with unchanged code, compare the runner `Image:` line in the job log first.
- Windows CI checks text files out with **CRLF** → a test that compares a generated file byte for byte must normalise line endings (CI #138: `lang/explorer2.pot`); catalogs are pinned to LF in `.gitattributes`. The extractor normalises CRLF in the sources too (rustc reads multi-line string literals with LF; CI #145: the recovery tool's usage text).
- Slint layouts never squeeze a one-line `Text` (its min width = full width): a too-long text pushes its row out of the panel instead of being cut – detect it against the parent/clip box (`uidump::cut_off`), not by the text's own box; std `CheckBox` text cannot wrap → `CheckRow`. Wrapped rows are taller: a settings item can end up below the visible panel → tests call `ui_scroll "<name>"` (wheel over its visible top) before `ui_click` (L5, [80c]).
- UI dump: a heading and the control it labels can share one name (“Sprache · Language” = heading `Text` + `ComboBox` accessible-label) → click the control with `ui_click "<name>" 2`; a std `ComboBox` shows its popup entries as own items (`ui_click "English"`), its current value is not in the dump.
- NTFS updates a folder's last-write time **lazily** (a moment after files were created in it) → tests that compare folder times right after building a tree need a settling pass (CI #155, `search::refresh` test).
- Processes that Windows starts (Win+E, folder double-click) do not inherit `EXPLORER2_LANG` from the test → they show the runner's system language; check them via process/trace, not by UI text.
